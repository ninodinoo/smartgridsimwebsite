// 01 — Was?

Eine Stadt, deterministisch simuliert.

Eine mittelgroße Stadt (~150 000 Einwohner-Äquivalent) mit ihrem gesamten Strombedarf, allen Erzeugern, Speichern und Sektorkopplungs-Lasten — modelliert auf Schul-Physik-Niveau, aber wissenschaftlich verteidigbar.

Bei gleichem Seed ist das Wetter identisch reproduzierbar. Damit lassen sich verschiedene Steuerungsstrategien fair vergleichen — die einzige Variable ist die Steuerung.

  • ▸ 96 Zeitschritte à 15 Minuten = 24 Stunden
  • ▸ Vollständige Energiebilanz pro Tick
  • ▸ CO₂-Buchhaltung, Frequenz, Wirtschaftlichkeit
  • ▸ Reproducibility-Hash in jedem Output

// 02 — Wie?

Sechs Schichten, klar getrennt.

Die Engine kennt keine Strategie. Sie führt nur Physik aus. Steuerungen sind austauschbare Module, die zwischen den Ticks Sollwerte schreiben.

SCHICHT 1

Komponenten

PV, Wind, Speicher, Lasten. Jede Klasse implementiert step(dt, ctx) → P [MW].

P = G · A · η_module · η_inv
SCHICHT 2

Wetter & Daten

SyntheticWeather (Seed-deterministisch) oder CsvWeather (DWD/PVGIS-Daten via CSV).

irradiance, wind, temperature
SCHICHT 3

Engine

Tick-Engine: ruft alle Komponenten auf, summiert Bilanz, bucht CO₂ und Renewable, schreibt JSON-State.

P_total = Σ P_i
SCHICHT 4

Controller

Strategien: naive, rule_based, … Mutieren Komponenten zwischen Ticks.

setpoint_mw, curtailment
SCHICHT 5

KI-Schnittstelle

JSON-Snapshot pro Tick → LLM → JSON-Action zurück. AnthropicAIController nutzt Prompt-Caching.

decide(state) → action
SCHICHT 6

CLI

Click-basiert, persistiert State zwischen Aufrufen. Macht jeden externen Controller trivial steckbar.

sgsim init / state / dispatch / tick
terminal
# 24-Stunden-Lauf mit regelbasierter Steuerung
$ sgsim experiment run --controller rule_based --seed 42 --out rb.csv

# Tick-by-Tick mit eigener Logik / KI
$ sgsim init
$ sgsim state                          # JSON-Snapshot lesen
$ sgsim dispatch h2_gasturbine 100    # Sollwert setzen
$ sgsim dispatch -- pumpspeicher_alpental -50
$ sgsim tick                           # einen Schritt vorwärts

# KI-Brief direkt aus dem Tool
$ sgsim brief
// 03 — Warum?

Die Forschungsfrage.

HYPOTHESE H1

Eine LLM-basierte Steuerung senkt die Anzahl der Brownouts in einem 100 %-erneuerbaren Stromsystem um mindestens 30 % gegenüber einer regelbasierten Steuerung — ohne dass CO₂ oder Energieverschwendung signifikant steigen.

📉

Das Problem

Heuristiken kennen keine Mehrtick-Vorausschau. Sie reagieren rein auf die aktuelle Bilanz — ohne zu antizipieren, wann Speicher gebraucht werden.

🧠

Die Hypothese

Ein LLM kann Wettervorhersagen interpretieren, mehrere Stunden vorausplanen und unerwartete Situationen flexibel angehen — eine Fähigkeit, die Heuristiken fehlt.

📊

Der Test

n = 30 Seeds × 2 Strategien, Welch-t-Test, Cohen's d. Pre-registrierte Hauptmetrik: brownout_steps. Reproducibility-Hash für jeden Lauf.

// 04 — Erste Ergebnisse

Was die Heuristik gut kann — und wo sie scheitert.

Werte aus einem 24-Stunden-Lauf mit Seed 42 im 100 %-erneuerbaren Default-Szenario. Beide Strategien sehen identisches Wetter.

Metrik Naive (statisch) RuleBased (smart) Δ
CO₂-Emissionen 33 kg 28 kg −15 %
Energieverschwendung (Surplus) 678 MWh 103 MWh −85 %
Brownout-Ticks (von 96) 38 63 +66 %
Erneuerbaren-Anteil 56 % 57 % +1 %
Der spannende Befund

Die regelbasierte Strategie reduziert Verschwendung dramatisch (−85 % Surplus), erleidet aber 66 % mehr Brownouts. Genau dieser Trade-off ist der Spielraum, in dem eine KI besser sein könnte — wenn sie vorausschauend mit Speichern umgeht. Die Hauptauswertung über n=30 Seeds steht aus.
